# Published course definitions

Course publication now retains an explicitly reviewed definition in the single protected event store. Version 2 preserves course code, catalog title, fixed credit thousandths, prerequisite identities, an optional transcript title and an optional plain-text catalog description. Earlier version-1 definitions retain their original four fields and are never rewritten. Explicit section binding now retains a selected published version for an empty section. Both publication and binding use the existing event table.

## Staff workflow

1. Apply `20261108000003_CreateSisCourseDescriptionsTable` and `20261108000004_CreateSisCourseVersionBindings` through the normal migration runner before using the updated catalog or portal. Neither migration has been applied to a working database by development tooling.
2. Open **Academic catalog → Courses**, then open the course. Save any course or prerequisite edits first.
3. Select **Titles & description** to enter a transcript title (up to 80 characters) and a plain-text description (up to 10,000 characters). Paragraphs are supported. Save the draft; blank fields remain explicitly unspecified. Existing rows are not backfilled.
4. Select **Published definitions**. Earlier definitions are shown in pages of 20, oldest first; expand a version to inspect it.
5. Enter the reason for publication and select **Review current definition**.
6. Check the code, catalog/transcript titles, description, credits and prerequisite references. The review displays the trusted effective time captured when that review was prepared.
7. Select **Publish reviewed definition**. The confirmation displays the retained version number and publication reference.

Publication preserves a definition for institutional reference. It is separate from activating a course or publishing its course offerings. A later course edit changes the working catalog row; it does not replace a retained published definition. Publishing again creates another version linked to its predecessor. The first publication records a decision made now; no migration silently turns an existing row into a claim about past academic requirements.

## Bind a section to a publication

1. Publish the intended course definition using the steps above.
2. Open **Academic catalog → Sections**, open an empty section, and select **Course definition**.
3. Inspect the available published versions and select one. Enter a reason and choose **Review section definition**. Neither selecting nor reviewing writes a binding.
4. Verify the section, course definition, version reference and reason, then choose **Retain reviewed definition**.
5. The screen now displays the retained definition. Later course edits or publications do not replace it. A different version requires another offering; no rebind action is available.

Binding requires `sis:catalog:manage`; registration management by itself is insufficient. The section and owning course are locked. Any enrollment record, including a closed enrollment, prevents a first binding. A section edit or an enrollment created after review invalidates the commit. This avoids assigning a present-day definition to existing students retrospectively. Sections whose earlier enrollment projection was removed during drop/add have no reconstructed past definition; the new binding is only a decision made now for future registrations.

Direct section creation still supports the separate binding action, and registration does not yet require every existing section to be bound. Existing unbound sections remain unbound, including populated ones; their historical version stays unknown. **Offering-plan publication now requires a retained or explicitly selected published definition for every section**, using the connected workflow below. Templates supply working defaults rather than guessing a publication version.

For a bound section, portal catalog/enrollment cards and staff section/registration/teaching lists read the retained course code, catalog title and credits; catalog descriptions also come from that version. New registrations evaluate the retained prerequisite membership, including an explicitly empty list. Individual and group registration reviews use the retained definition, and a newly added binding invalidates an earlier group review. Their academic-credit rows snapshot the retained code, selected transcript title (or retained catalog title) and credits, with the selected publication ULID stored as a separate reference. Later catalog changes do not change those snapshots. Operational course activity still controls whether an offering can accept registrations. Capacity, delivery, fees, faculty, instructional dates and policies are not versioned by this binding. A separate [section-publication workflow](section-publication.md) now retains instructional dates and reviewed offering facts; selecting those section versions for registration and completing policy references remain later stages.

Schema-1 definitions do not acquire schema-2 descriptions or transcript titles from today's catalog: absent earlier fields remain unknown. New transfer credits still follow their existing published-title workflow; transfer equivalencies and awards are not pinned by this section flow.

`SectionCourseVersionWasBound` records only the owning course and publication-version references. Its stream uses the section ULID and logical type `section_course_binding`, expected version zero and a single accepted decision. Actor, reason, effective/recorded times and operation receipt use the shared protected journal. The encrypted review token is actor/section bound; each request rechecks permission. An unchanged retry returns its original receipt even after enrollment or ordinary section edits. Competing first decisions cannot overwrite the accepted one. Journal append, retained definition, binding and audit commit together or roll back together.

`20261108000004_CreateSisCourseVersionBindings` creates three ordinary projection/reference tables, with no event payload table or backfill:

- `sis_course_versions`: normalized, shared cache of the exact selected publication, keyed by publication ULID. Schema-1 missing text stays null. Course publication events remain its authority.
- `sis_section_course_versions`: one section-to-publication reference, keyed by section ULID. The binding event remains its authority.
- `sis_credit_course_versions`: one reference for each newly created institutional credit from a bound section, keyed by credit ULID. Existing and transfer credits are not assigned guessed versions.

Registration reads the indexed projection rather than replaying catalog history for every student. Two sections using one publication share its cached definition. Before cache reuse, the binding command verifies it against the selected publication and rejects inconsistent contents. These projections require the same database access/retention controls as other catalog/academic projections. The future controlled rebuild coordinator must replay publication/binding history into isolated output and reconcile credit references; it must not clear live academic tables. Institutional credit creation, grades and drops now use [replayable academic-credit history](academic-credit-history.md); full section/policy references and controlled rebuild coordination remain outstanding.

During early drop/add, current credit references are removed with the current credit projection; the encrypted drop receipt preserves the prior reference. The section binding and authoritative publication/binding events remain. The existing late-drop workflow retains both credit and reference. Accepted registrations and early/late releases now use [registration history](registration-history.md); waitlists and full section/policy references remain outstanding.

Browser endpoints are POST requests under `/sis/sections/{id}/course-definition/`: `page/`, `review/` and `commit/`, retaining framework CSRF, private/no-store responses and debug suppression. Their responses are curated definitions or reviews, never raw event envelopes. Selection, review and confirmation use labeled native controls, preserve drafts in page memory and support keyboard access and narrow screens.

## Publish offering plans with retained definitions

1. Build an offering plan, or prepare one from an active offering template. Review and **Save section drafts** as before; this does not activate sections or publish course definitions.
2. Open the saved plan and select **Review publication**. The inline **Choose offering definitions** screen groups empty unbound drafts by course and lists the affected section codes.
3. Inspect a published version and choose it once for that course's grouped sections. Version pages preserve the selected version and publication reason. A course with no published definitions must be published first; its offering drafts remain saved.
4. Sections already bound to a publication display their retained definitions and cannot switch versions. If offerings of the same course need different definitions, bind those sections individually first; the grouped publication flow preserves those choices.
5. Enter the reason for offering publication and choose **Review definitions & publication**. Check the resolved definitions, credits, faculty, delivery, capacity, fees and self-registration choices. **Change definition choices** preserves the selection and reason. Reviewing writes no bindings or activation.
6. Choose **Publish reviewed sections**. New course-version bindings and all section activations commit together with the encrypted receipt and audit. A later failure rolls back the new events, projections, receipts and activations together. Previously accepted independent bindings remain intact.

This flow accepts up to 25 sections. Every unbound section needs an explicit publication choice belonging to its course. Missing, duplicate, unrelated and foreign-course selections are rejected; an unbound draft with enrollment records cannot receive a retrospective definition. A section, term, faculty or binding change invalidates the review. Later edits/publications of the working course do not substitute another definition for an explicitly chosen version; course activity still gates activation. Existing bound projection contents are verified against their protected publication before review and commit.

The review token is encrypted, bound to its staff member and offering-plan identity, and contains selected references and a context fingerprint rather than repeated course descriptions. Commit rechecks current permission, locks the operation, sorted sections, sorted courses and term, and verifies the same context. Each new binding has its own expected-version event/receipt and correlates to the offering-plan ULID. Its effective time is the trusted publication time; it is not backdated to draft creation or an abandoned review. The publication reason is protected in the binding context and existing encrypted offering receipt.

An exact retry returns the accepted publication receipt without repeating events or audit, even after ordinary section edits or enrollment. Another review or actor cannot reuse that completed operation. Published receipts retain the actual reviewed definitions instead of showing the original draft-save labels. Existing published development plans remain readable with their original receipts; no history or version references are invented for them.

The unreleased publication API now uses POST `/sis/catalog/offerings/{operation}/publication-setup/`, then `publication-review/` with `course_versions: [{section_id, version_id}, ...]` and `reason`, followed by `publish/` with only the returned `review_token`. Already bound sections may omit a selection; an explicitly supplied selection must match their retained version. The former revision-only publication request is no longer accepted. All calls retain catalog authorization, CSRF, private/no-store responses and debug suppression. Draft review/save APIs retain their existing revision contract.

No additional migration is introduced: this uses the existing `sis_catalog_operations` encrypted receipt and the tables from `20261108000004_CreateSisCourseVersionBindings`. Section binding uses compact version-2 review proofs; previously issued version-1 full-definition proofs and recorded event schemas remain supported. Course publication's bounded token allowance now accommodates the documented maximum multilingual description, prerequisite list and reason; this changes no retained event bytes.

## Storage, authorization and retry behavior

`CoursePublicationService` coordinates the command. `CoursePublicationId` identifies the existing course's publication stream, using Codefy aggregate/event types. `CourseDefinitionWasPublished` has separately reviewed version-1 and version-2 contracts in the shared registry. Version 1 retains the original four definition fields. Version 2 adds required keys for nullable `transcript_title` and `description`; null is distinct from pretending an older version recorded those fields. Other event classes still admit only their registered version 1. Unknown versions and incompatible shapes fail closed. Publication events contain the version ULID, predecessor version reference and exact definition. No independent publication payload table is created. `sis_course_descriptions` holds mutable text drafts and a rebuildable projection of the latest published text, version reference and stream position. Publication updates this projection within the journal/audit transaction; a failure rolls everything back. Retained events remain the authoritative published definitions.

The review is an authenticated encrypted token containing the snapshot, actor, operation ULID, expected stream version, reason and trusted effective time. The application checks current `sis:catalog:manage` permission for each review, commit and history-page request. A review is bound to its original staff member and course. Tokens remain in page memory and are not written to browser storage. Abandoning a review writes no event.

Publication locks the course row and uses expected-version append. The draft snapshot is compared within that same transaction. Changed code, title, credits, description, transcript title or prerequisite membership requires a fresh review. Text editing and basic course editing use the same revision token. Old saved version-1 publication retries remain valid; abandoned version-1 reviews cannot create a new incomplete publication after this upgrade. An unchanged retry uses the protected journal receipt and returns its original result, even after later draft changes or publications; it does not duplicate the event or audit entry. Permission revocation still prevents the retry. Later audit/projection failure rolls back the event, head and receipt together.

All events use the existing journal encryption, purpose binding, schema validation and integrity verification. The publication context records the authorized actor, review's effective time, operation/correlation reference and protected reason; journal insertion time records when publication committed. The review's effective time is explicit, not inferred from old course data.

Text editing uses GET/POST `/sis/courses/{id}/text/`, guarded by `sis:catalog:manage` and the shared revision. Browser publication endpoints are POST requests under `/sis/courses/{id}/publication/`: `review/`, `commit/` and `page/`. They retain framework CSRF, private/no-store responses and debug suppression. The history page returns curated catalog definitions, version references and effective/recorded times. It does not return raw event envelopes, audit actors, credentials or protected reasons. Cursors freeze the initial page boundary and cannot be used across streams.

`CoursePublication` supports bounded incremental replay while keeping only its current version reference in memory; complete framework replay is also tested. Reading/replaying publications performs no writes, billing or activation. The current UI lists prerequisite identities rather than claiming that today's prerequisite titles are historical snapshots.

## Published presentation and academic snapshots

Saving course text does not change the portal. Only a successful publication updates the public description projection. Portal cards use native keyboard-accessible disclosure controls and escape all descriptions as plain text; HTML-looking text is displayed literally. Report Studio's Sections dataset exposes **Current published transcript title** and **Current published course description** through a unique left join, preserving sections without descriptions. Those are current catalog values, not historical reporting snapshots. Separate **Retained course version**, **Retained course code**, **Retained catalog title**, **Retained transcript title** and **Retained credits** fields describe the explicitly bound version, remaining null for unbound sections. The academic-credit dataset also exposes its retained version reference. These unique left joins preserve unbound rows; drafts and raw event streams are not exposed.

New registrations from bound sections snapshot the selected version as described above. Unbound registrations and new transfer academic-credit records snapshot the currently published transcript title when specified, otherwise use the current course title as before. Later draft edits or publications do not rewrite existing credits or issued documents. Course cloning copies the source's reviewed draft text into the new inactive draft, without copying publication history or activating its description. The existing basic CSV importer still imports its original code/title/fixed-credit fields; text can be authored after import.

The projection adapter can rebuild published text from retained events into an isolated target; it does not perform publication, activation, charges or messages. Rebuilds must preserve draft authoring data and must not clear live tables. Full projection rebuild coordination and maintenance controls remain future work.

## Scope still to complete

This is a staged published-definition and explicit section-binding slice, not the completed academic-history retrofit. Only deliberately bound empty sections and their new institutional credits retain course-version references. Offering-plan publication now requires explicit retained definitions; direct creation and existing/transfer records still have their staged boundaries. Section publications now retain reviewed offering facts; selecting them for registrations, complete policy references, closed-record replacements and controlled projection rebuild operations remain pending. Institutional and transfer award histories are implemented separately. Publishing a course alone does not protect every downstream academic read.

Normalized subject/department/level references, variable-credit policies and publication retirement/amendment policy remain in the [legacy field review](academic-history-field-review.md). [Global/program grading scales](grading-scale-setup.md) now provide immutable grade definitions; complete section-level policy references remain outstanding. Restore those through explicit schema versions, authoring and authorized reads rather than altering the meaning of retained version-1 events. Bound sections now evaluate their retained prerequisite membership, and accepted seat decisions now have their own protected history. Full prerequisite/co-requisite expressions and historical eligibility policy coverage remain outstanding. Existing permission grants and institution-specific approval requirements remain applicable; a recorded reason does not establish a second-person approval.

Next, retain the remaining historically meaningful classification and policy fields and select published section/policy versions for new registrations and academic facts. Earlier unknown definitions must remain unknown. No working database was accessed or changed for this implementation.
