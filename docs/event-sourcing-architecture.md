# Historical integrity and selective event sourcing

Adopted direction, 2026-11-08. [Event-sourcing rationale](event-sourcing.md) governs continued development. Security, student privacy and preservation of historical academic facts take priority over feature breadth. This review identifies required retrofits; it does not certify legal compliance or describe unimplemented protections as complete. Apply it with the [academic field review](academic-history-field-review.md) and existing [domain organization](domain-organization.md).

## Implementation progress

The [single protected journal](event-history-foundation.md) now backs both the domain-owned port and Codefy’s framework port. The migration copies and verifies existing User/financial events before removing the old event table; original context gaps are explicit. 46 reviewed event types, with one current course format, degree-requirement schemas v1/v2/v3/v4 and independent course-group schemas v1/v2, authenticated encryption, version checks, atomic receipts and bounded replay are implemented. Academic SQL writers and full command-context attribution still require conversion. External integrity anchors, operational retention and complete projection rebuild tooling remain outstanding.

Explicit [course subjects](course-subjects.md) now retain normalized subject identity/code/name through course publications and bound portal/report read models. Earlier subjects remain unknown.

The first [course-publication slice](course-publication.md) retains reviewed definitions, including optional transcript titles and descriptions, without changing earlier versions. New course confirmations now capture acceptance time through expiring, actor-bound reviews and recheck permission after locks/replay. Earlier stored times and completed receipts remain unchanged; pending older reviews require a fresh review. Explicit binding now pins an empty section to a chosen publication and preserves that reference and resolved values on new institutional credits. Portal, registration and staff section reads use the retained definition; reports distinguish retained and current values. Offering-plan publication now requires deliberate version selection and atomically binds/activates its drafts. Directly created and earlier unbound sections retain their staged behavior; full section/policy versions and remaining catalog/reference fields still require conversion. [Enrollment history](registration-history.md) now records accepted seats and releases without inventing earlier decisions.

[Section publications](section-publication.md) now retain reviewed instructional dates, term context, capacity, delivery, canonical faculty identity and fees as immutable versions. Indexed section-version selection and reviewed future-registration amendments now retain the applicable reference in new enrollment/academic facts while preserving earlier references and charges. Offering-plan confirmation now retains reviewed section publications/selections with activation in one transaction. Full policy definitions remain outstanding.

## Persistence boundaries

| Context | Target source of truth | Read/edit boundary |
| --- | --- | --- |
| Student finance, journal and billing decisions | Event-sourced monetary/rule decisions and explicit reversals | Statements and accounting projections remain reconstructible; a replay never posts another charge or refund. |
| Registration and seat allocation | Accepted registrations, cancellations, withdrawals, selected credits, seat/waitlist decisions and reasons | Section capacity is enforced atomically. Waitlists remain a future feature, not an existing guarantee. |
| Academic records | Credit awards, grade assignments/amendments, repeat/exclusion decisions and graduation/credential decisions | Corrections append new facts. Transcripts and degree-audit inputs use the retained course, grading and policy versions. |
| Student lifecycle and program assignments | Matriculation, program/primary changes, leaves/returns, standing and load determinations | Capture effective dates and recorded times separately. Sensitive reasons have separate access controls. |
| Admissions | Consequential submission, decision, offer/acceptance and matriculation transitions | Ordinary drafts need not be event sourced. Store protected document/submission references, not duplicated answers or document bytes in events. |
| Catalog, sections and academic policy | Stable identities with immutable published revisions and attributed publication/retirement/amendment decisions | Drafts can use CRUD. Offerings and academic facts pin applicable revisions; later catalog edits do not rewrite history. |
| Profiles, reference data and basic facilities | CRUD with appropriate audit, authorization and retention | CRUD does not waive privacy or audit requirements. Historically meaningful decisions and published reference versions remain preserved. |

The existing User aggregate also uses framework event sourcing. Its recorded credential/profile payloads now use the same encrypted journal; projection privacy and retention still need review, and it is not a reason to event-source every person/contact field.

## Required event contract

Each authoritative event needs a stable event ID; aggregate type/ID and expected stream sequence; stable logical event type and schema version; a durable operation/idempotency key; trusted actor or explicit system actor; correlation/causation references; recorded UTC time; and the business effective date/time with the institution’s timezone where relevant. Corrections need reason/approval references and the event/decision they supersede. These fields must originate from trusted application context rather than user-supplied actor or clock values.

Payloads contain the smallest facts needed to replay the decision and references to immutable course, section, curriculum, grade-scale and policy revisions. Prior facts remain recoverable through their original events; do not copy whole student profiles into every event. Names, institutional IDs, medical narratives, uploaded documents, credentials and freeform reasons require deliberate minimization and protected storage. Authorization/approval evidence must remain interpretable when today’s roles or account details change.

Distinguish **effective time** from **recorded time**. A grade correction recorded today may take effect in a prior term. Support both “what is effective for that term now?” and “what did the institution know when it issued that transcript?” Retain recorded issuance facts and selected academic revisions so both questions have reproducible answers.

New SIS entity/operation identities remain ULIDs. Preserve existing framework financial event IDs and stored event type names unless an explicit, tested conversion changes them; do not rewrite financial history merely to rename classes or identifiers. During alpha, prefer a single current model and explicit, tested schema changes over compatibility layers for intermediate builds. Inspect existing history before changing a stored shape and deliberately convert any affected recorded facts when necessary. Stabilize external compatibility during release-candidate planning; never use arbitrary class deserialization or silently replace business facts.

## Concurrency, transactions and projections

AJAX search and AJAX updates use the same authorized backend boundaries. Search reads query projections; consequential commands reconstruct the relevant authoritative state and retain transaction locks where needed. Controlled replay supports verification and recovery without repeating external business actions.

Event sourcing does not remove capacity or eligibility races. Use expected stream versions and database uniqueness, with explicit shared section/seat serialization where multiple students compete. A trusted durable server-side request sequence can establish accepted order within its defined scope; timestamps, ULIDs and browser clicks alone do not define global fairness.

Initially retain the existing single-database unit of work: event append, academic/current-state projections, financial effects, receipt and required audit must commit together or all roll back. Multi-stream operations need deterministic lock order and expected versions. A retried command must return its original outcome without another enrollment, grade amendment or financial posting. Do not introduce asynchronous eligibility, capacity or balance decisions as a shortcut.

Read models may duplicate data for query performance, but have no independent authority to amend historical facts. Projectors are deterministic and versioned; replay performs no external calls, messages, billing or access grants. Background side effects require a durable outbox and idempotent consumers when introduced; jobs carry protected references rather than student payloads. Projections must not join mutable catalog/grade definitions to reinterpret past awards.

Provide paged/bounded stream processing, projection checkpoints, failure recovery and reconciliation. Rebuild into isolated output, verify counts/balances/academic totals, then deliberately switch readers; never clear live academic/financial tables and hope a replay completes. Persist published policy inputs needed for deterministic decisions, while student degree evaluation and allocation still need their specified implementation.

## Security and retention

Application writes are append-only for authoritative events. Operational database roles should separate append, read and projection maintenance privileges; projection rebuilds must not grant event deletion. Add tamper detection with verified canonical envelopes and protected integrity keys/anchors, plus independently protected backups and restore exercises. A hash stored beside mutable data alone does not defeat a privileged attacker.

Protect sensitive payloads with authenticated encryption and versioned key references, secure key rotation/recovery and failure-closed decryption. Inventory current financial/User payloads before introducing academic facts. Preserve the existing rule against student payloads, credentials or reasons entering logs, browser storage or queue bodies. Raw streams must not become a general Report Studio dataset or a browser debugging view. History reads require current relationship/role authorization; registrar, faculty, finance and transcript access remain separate.

Define institutional retention categories, legal holds, access/export records and correction procedures before production use. “Append-only” is not permission to retain unnecessary personal information forever. Resolve erasure/redaction and key-retirement policies explicitly, including backups and historical documents, without silently corrupting lawful academic/financial evidence. Event sourcing supports evidence; a particular legal compliance claim requires the applicable institution/jurisdiction and operational controls.

Early drop/add still removes the current enrollment/transcript projection and reverses the original course charge. Restricted registration/drop events remain under the applicable retention/access policy. Later drops keep policy-selected grades and charges. A retake creates a new attempt and billing-term identity. Never expose a removed early-drop record on a student transcript merely because its protected history exists.

## Retrofit order and completion gates

1. **Shared secure event foundation:** settle the typed envelope, registered schemas, authenticated payload protection, expected-version append, operation receipts, effective/recorded times and bounded replay. Review existing finance and User event payloads; preserve replay and posting behavior. Prove rollback and tamper/corruption failure behavior before adding sensitive academic streams.
2. **Published academic definitions:** restore the missing fields from the [legacy field review](academic-history-field-review.md) as normalized reference data and immutable course/section/grading/policy revisions. A stream containing too few facts cannot later reconstruct the missing academic context.
3. **Academic awards and grading:** event-source initial credit creation and final-grade assignment/amendment as one coherent history. Pin course/section/grade policy versions, require attributable correction reasons/approval policy and rebuild transcript inputs exactly. Do not merely log that an SQL UPDATE happened and call that event sourcing.
4. **Registration and drop lifecycle:** convert every registration entry point, batch, early/late drop, hiatus closure and financial coupling. Test competing final-seat requests and uncertain retries. Introduce waitlisting only with a defined ordering/allocation policy.
5. **Student programs/lifecycle and admissions:** convert consequential transitions, retained curriculum/cohort assignment and dated status/load decisions. Preserve transfer/hiatus/transcript history and evolve them into the same guarantees. Degree-audit evaluation awaits the requirements specification.

For each slice, inventory all write entry points and readers, define stream ownership and facts, convert commands and projections together, and prove deterministic replay/as-of history, authorization, stale/duplicate rejection, atomic rollback, protected payloads and unchanged financial invariants with fictional fixtures. Update current-status documentation only after those checks pass. Existing metadata/receipts must not be presented as completed event sourcing.

Existing rows may be imported as explicitly labelled **observed baseline** events with source/provenance and observation time. Preserve existing recorded history when it is available and verified. Never manufacture historical grade changes, actors, approval dates, request order or earlier policy versions from a current-state snapshot. Breaking schema changes are permitted before release, but no working database is reset or converted as part of this review.
